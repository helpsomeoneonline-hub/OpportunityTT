# Matching rules

The first matching engine is rules-based and explainable.

## Hard requirements

A hard requirement can block a match. Examples:

- Required licence
- Required certification
- Legally required credential
- Explicit minimum qualification when marked mandatory

Hard requirements should never be hidden inside a weighted percentage.

## Soft factors

Soft factors improve or weaken fit:

- Job family/category
- Skills
- Experience
- Preferred location/region
- Employment type
- Salary compatibility
- Availability
- Nice-to-have qualifications

## User-facing labels

Avoid fake precision such as "92.4% perfect match".

Use:

- **Strong Match**
- **Good Match**
- **Partial Match**
- **Not Eligible**

The UI should always show reasons, for example:

- Matches: Heavy-T licence, driving experience, Central preference
- Missing: employer prefers 3 years; candidate has 2

## Photos

Profile photos are optional and are never an input to ranking or eligibility.

## Employer visibility

Future employer discovery must be opt-in. A candidate can use job recommendations without making their profile searchable by employers.
