# OpportunityTT MVP

## Problem

Useful vacancies are fragmented across newspapers, job boards, company pages and other sources. Job seekers repeatedly search multiple places and still miss opportunities.

## MVP promise

A job seeker creates a lightweight profile once. OpportunityTT then surfaces jobs that fit that profile and explains the match.

## Primary user

A Trinidad & Tobago job seeker who wants relevant job alerts without manually checking many sources every day.

## MVP journey

1. User creates a quick profile.
2. User selects preferred job areas and locations.
3. Clean job records enter the database.
4. The rules engine evaluates eligibility and fit.
5. User sees Strong / Good / Partial matches with reasons.
6. User saves, dismisses or opens the original application source.
7. Notification preferences determine which new matches can trigger an alert.

## Deliberately postponed

- Employer candidate browsing
- Direct employer-to-candidate messaging
- In-app applications
- Interview scheduling
- Candidate ratings
- Photo-based ranking
- Black-box AI scoring
- Paid subscriptions

These are postponed because a two-sided marketplace has a cold-start problem. The job-seeker product must be useful before employer adoption.

## Success criteria for Milestone 1

- Imported jobs are stored in a consistent structure.
- Obvious duplicates are held back.
- Mandatory requirements can disqualify an otherwise strong match.
- Matching produces human-readable reasons.
- A synthetic candidate gets sensible ranked results.
